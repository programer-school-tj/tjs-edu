# Нақшаи техникии Offline-first барои TJS Edu

## Ҳолати воқеӣ

Дар версияи ҳозира Service Worker танҳо App Shell-ро кеш мекунад: саҳифаи асосӣ, manifest, нишони барнома ва файлҳои статикӣ. Ин имкон медиҳад интерфейс дар баъзе ҳолатҳо бе интернет кушода шавад, аммо маънои кори офлайнро надорад.

Қисман амалӣ шудааст:
- навбати IndexedDB барои сабти давомот; сабт пеш аз кӯшиши фиристодан нигоҳ дошта мешавад;
- фиристодани навбати давомот ҳангоми боз шудани саҳифа ва барқарор шудани интернет;
- калиди ягонаи амалиёт ҳамчун `Idempotency-Key` барои retry-и бехатар;
- кеши рӯйхати давомот бо калиди корбар/муассиса/синф/сана ва муҳлати 24 соат;
- нигоҳдории офлайнии танзимоти ҷадвали дарсӣ: ҳангоми набудани интернет танзимот дар IndexedDB ба навбат меафтад ва баъди боз шудани интернет ба endpoint-и иҷозатсанҷидашуда фиристода мешавад; endpoint ҳолати танзимотро бо upsert нигоҳ медорад.

Ҳанӯз амалӣ нашудааст:
- кеши муассисаҳо ва синфҳо барои интихоби онҳо баъди refresh-и офлайн;
- нигоҳдории таҳрирҳои экран пеш аз пахши «Сабт»;
- навбати тағйирот барои сабти ҷадвали дарсӣ (дарсҳо), сарбории омӯзгорон, тарификатсия ва маош; танзимоти ҷадвал ҳоло ягона ҷараёни офлайнии ин модул аст;
- ошкор ва ҳал кардани ихтилофи маълумот (conflict) дар байни дастгоҳҳо;
- идоракунии пурраи синхронизатсия ва тозакунии маълумоти маҳаллӣ ҳангоми баромадан аз ҳисоб.

Танзимоти ҷадвал танҳо баъди қабул шудани ҷавоби муваффақ аз сервер ҳамчун анҷомёфта ҳисоб мешавад. Агар сервер ҷавоб надиҳад, амалиёт дар навбат мемонад ва ҳангоми боз шудани интернет такроран фиристода мешавад. Ҳангоми retry сабти танзимот бо upsert нав мешавад; аммо audit log метавонад барои retry-и баъди гум шудани ҷавоби сервер сабти такрорӣ дошта бошад. Ин ҳолат бояд пеш аз эълони офлайн барои истифодаи оммавӣ бо idempotency-и серверӣ такмил дода шавад.

Кеши давомот ба ID-и корбари воридшуда ҷудо карда мешавад ва танҳо майдонҳои зарурии рӯйхатро нигоҳ медорад. Ин ҷудокунии ҳисобҳоро беҳтар мекунад, аммо IndexedDB рамзгузории маҳаллӣ нест; дар дастгоҳи муштарак аз ҳисоби корбар баромадан ва қулфи дастгоҳ муҳим аст. Кеш баъди 24 соат кӯҳна ҳисоб шуда, истифода намешавад.

То пайваст шудани ҳамаи қисмҳои боқимонда, дар интерфейс набояд ваъдаи «пурра офлайн кор мекунад» дода шавад.

## Меъмории пешниҳодшуда

### 1. IndexedDB

Маълумоти маҳаллӣ бояд аз рӯйи муассиса ва корбар ҷудо нигоҳ дошта шавад. Ҳар сабт бояд ҳадди ақал ин майдонҳоро дошта бошад:
- `id`: UUID-и маҳаллӣ;
- `institutionId`: муассисаи соҳиби сабт;
- `entityType`: навъи сабт, масалан attendance ё timetable;
- `entityId`: ID-и сабти серверӣ, агар аллакай мавҷуд бошад;
- `payload`: маълумоти иҷозатдодашуда;
- `updatedAt`: вақти охирини тағйири маҳаллӣ;
- `syncState`: pending, syncing, synced ё failed.

Маълумоти махфии аутентификатсия, парол ва токенҳо набояд ба навбати офлайн нусхабардорӣ шаванд.

### 2. Навбати тағйирот

Ҳар амали офлайн бояд бо `operationId`-и беназир сабт шавад. Навбат бояд пайдарпай коркард шавад, то тағйироти вобаста тартиби худро нигоҳ доранд. Амалиёт танҳо баъди тасдиқи сервер ҳамчун synced қайд карда мешавад.

### 3. API ва бехатарӣ

- Ҳар endpoint-и тағйирдиҳанда бояд иҷозати корбар ва муассисаро аз нав санҷад.
- Сервер бояд `operationId`-ро барои idempotency истифода барад, то retry сабти такрорӣ насозад.
- Санҷиши нақш, муассисаи фаъол ва маҳдудияти FREE/PRO набояд танҳо ба браузер такя кунад.
- Ҳангоми иваз шудани муассиса ё баромадан аз ҳисоб, маълумоти маҳаллии иҷозатдодашуда бояд ҷудо ва боэҳтиёт идора шавад.

### 4. Ихтилофи маълумот

Қоидаи умумии «охирин навишт ғолиб» барои ҳамаи модулҳо бехатар нест. Барои давомот, ҷадвал, тарификатсия ва маош сиёсати алоҳида лозим аст. Масалан, сабти маоши тасдиқшуда набояд бо sync-и кӯҳна хомӯшона иваз карда шавад. Conflict бояд ба корбар бо маълумоти муқоисашаванда нишон дода шавад.

## Тартиби татбиқ ва санҷиш

1. Қабати IndexedDB бо версиябандии schema ва санҷишҳои unit.
2. Навбати амалиёт бо operationId, тартиб, retry ва нигоҳ доштани ҳолати failed.
3. Пайваст кардани як ҷараёни камхатар, аввал давомот, ба навбат ва endpoint.
4. Санҷиши офлайн/онлайн, refresh, баста шудани браузер, retry, duplicate ва ду дастгоҳ.
5. Танҳо баъди муваффақ шудани санҷишҳо пайваст кардани ҷадвал, тарификатсия ва маош бо қоидаҳои conflict-и махсус.

## Меъёри қабули Offline-first

Хусусият танҳо вақте «тайёр» ҳисоб мешавад, ки корбар метавонад бе интернет сабт созад, саҳифаро нав кунад ё браузерро боз кунад, пас аз барқарор шудани интернет сабт як маротиба ба сервер гузарад, натиҷа дар дастгоҳи дигар намоён шавад ва ҳангоми ихтилоф маълумот гум ё худсарона иваз нашавад.

**Эзоҳ:** ин ҳуҷҷат нақшаи татбиқ аст, на далели он ки Offline CRUD аллакай кор мекунад.
