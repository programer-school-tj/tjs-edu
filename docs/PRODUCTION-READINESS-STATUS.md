# Вазъи омодагии TJS Edu

Ин ҳуҷҷат рӯйхати воқеии корҳои санҷидашуда ва монеаҳои боқимондаро нигоҳ медорад. Сабзи CI маънои омода будани барнома барои истифодаи воқеии мактабҳоро надорад.

## Санҷишҳои анҷомшуда

- Насби вобастагиҳо, TypeScript, тестҳо ва сохтани frontend дар GitHub Actions дар commit-и `c89bc113453b836a3e07c39bc7edcc4300b00455` муваффақ гузаштанд.
- API ва PostgreSQL дар сохтори Docker Compose пешбинӣ шудаанд.
- Барои тарификатсия ва маош муҳаррири Excel бо нигоҳдорӣ ва чоп мавҷуд аст.
- Барои ҷадвали дарсӣ воридоти Excel ва муҳаррири ҷадвал мавҷуд аст.
- Дар commit-ҳои `06a0fdd`, `7d3b594` ва `239fafa` fallback-и маҳаллии Excel илова шуд: агар бланки Floot дастрас набошад, муҳаррир шакли муваққатии маҳаллӣ месозад. Барои се навъи бланк санҷиши сохтани workbook ва round-trip-и XLSX илова шудааст; натиҷаи CI барои commit-и охирин ҳанӯз бояд тасдиқ шавад.

## Монеаҳои тасдиқшуда

### 1. Бланкҳои аслии Excel

Саҳифаҳои тарификатсия ва маош ба файлҳои бланки берунии муҳити Floot такя мекарданд. Файли маҳаллии `public/templates/tjs-edu-templates.xlsx` файли дурусти XLSX нест ва ҳамчун бланки расмӣ истифода намешавад. Барои кам накардани қобилияти кор дар нашри мустақил, муҳаррир ҳоло ҳангоми дастнорас будани файли беруна шакли муваққатии маҳаллиро месозад. Ин fallback барои тарификатсия, маош ва ҷадвали дарсӣ сохта шудааст.

**Корҳои зарурӣ:** бланкҳои аслии тасдиқшудаи корбарро аз нав дастрас кардан; ҳар кадомро бо ExcelJS кушода, номи варақҳо, диапазонҳо, формулаҳо, андозаи саҳифа ва майдонҳои чоп санҷидан; баъд онҳоро ҳамчун файлҳои маҳаллии `public/templates/` ҷойгир карда, fallback-ро бо шакли расмӣ иваз кардан.

То гирифтани файлҳои аслӣ мувофиқати чоп ба шакли расмии муассиса тасдиқ карда намешавад. Fallback танҳо барои воридот, нигоҳдорӣ, содироти XLSX ва чопи муваққатӣ аст.

### 2. Почтаи электронӣ ва тасдиқи ҳисоб

- Воридшавӣ бо почта ва парол мавҷуд аст.
- Рамзи якдафъаина ҳоло дар ҷараёни барқарорсозии парол истифода мешавад, на ҳамчун тасдиқи ҳатмии бақайдгирӣ.
- Дар endpoint-и барқарорсозии парол суроғаи фиристанда ҳоло `noreply@example.com` аст ва бояд бо домени тасдиқшудаи ирсолкунандаи почта иваз карда шавад.
- Пеш аз нашри мустақил бояд провайдери почта, домени фиристанда ва танзимоти махфии сервер муайян карда шаванд.

### 3. Кори офлайн

Service Worker интерфейс ва файлҳои статикиро кеш мекунад. Ин ҳанӯз кафолати сабти офлайнии ҳамаи маълумот нест. Навбати маҳаллии баъзе маълумот мавҷуд аст, аммо барои ҳамаи модулҳо санҷида нашудааст.

**Корҳои зарурӣ:** навбати умумии амалиётҳои офлайн, нигоҳдории маҳаллӣ, такрори бехатари дархостҳо, ҳал кардани ихтилофҳои ҳамоҳангсозӣ ва санҷиши ҷудогонаи ҷадвали дарсӣ, тарификатсия, маош ва кормандон.

### 4. Нашри интернетӣ

Дастури Hetzner омода аст, аммо сервер, домен, HTTPS, backup-и беруна ва барқарорсозии санҷидашуда ҳоло тасдиқ нашудаанд. PR №1 бояд баррасӣ ва ба `main` ҳамроҳ шавад, пеш аз он ки дастури нашр истифода гардад.

### 5. Ҷудокунии маълумоти муассисаҳо

- Мигратсияҳои `002_tenant_integrity.sql` ва `003_teaching_loads_and_shifts.sql` мавҷуданд. Мигратсияи 002 барои робитаҳои асосӣ (синф/омӯзгор, хонанда/синф, маош/корманд, маош/тариф, давомот ва ҷадвал) foreign key-ҳои таркибии `institution_id + id` месозад.
- Endpoint-ҳои санҷидашудаи кормандон, тарификатсия ва маош узвияти директорро барои муассисаи интихобшуда месанҷанд; сабти ҷадвал низ иҷозати директорро месанҷад.
- Ин муҳофизатҳо қадами мусбатанд, аммо санҷиши пурраи ҳамаи endpoint-ҳо ва санҷишҳои манфии cross-tenant ҳанӯз лозиманд. Мавҷуд будани foreign key танҳо иҷозати API-ро иваз намекунад.

- Мигратсияи нави `015_attendance_student_class_integrity.sql` робитаи давомотро бо се сутун (`institution_id + class_id + student_id`) месанҷад. Ин кафолат медиҳад, ки хонанда на танҳо ба ҳамон муассиса, балки маҳз ба ҳамон синф тааллуқ дошта бошад.
- Барои ин қоида санҷиши сохтории SQL дар `tests/attendanceClassIntegrity.test.ts` илова шуд. Ин санҷиш матни мигратсияро месанҷад; иҷрои воқеии маҳдудият бо PostgreSQL ҳанӯз бояд дар санҷиши интегратсионӣ тасдиқ шавад.
- Санҷиши интегратсионии `tests/attendanceClassIntegrity.integration.test.ts` илова шуд. Он дар schema-и ҷудогонаи муваққатӣ мигратсияҳои 001, 002 ва 015-ро ба PostgreSQL татбиқ карда, сабти дурустро қабул ва ду ҳолати нодурустро (хонандаи синфи дигар ва хонандаи муассисаи дигар) рад мекунад. Санҷиш бо `TEST_DATABASE_URL` ё `DATABASE_URL` фаъол мешавад; бе он skip мешавад. Натиҷаи CI барои commit-и ин тағйирот ҳанӯз бояд санҷида шавад.

### 6. Баррасии иҷозатҳои API ва бақайдгирии муассиса

Файлҳои зерин дар branch-и корӣ хонда шуданд: `endpoints/institutions/create_POST.ts`, `endpoints/institutions/list_GET.ts`, `endpoints/staff/list_GET.ts`, `endpoints/staff/create_POST.ts`, `endpoints/classes/create_POST.ts`, `endpoints/tariffs/create_POST.ts`, `endpoints/payroll/create_POST.ts`, `endpoints/payroll/list_GET.ts`, `endpoints/timetable/create_POST.ts` ва `endpoints/timetable/list_GET.ts`.

Натиҷаҳои тасдиқшуда аз хондани код:
- Бақайдгирии муассиса онро бо ҳолати `pending` месозад ва барои дархостдиҳанда узвияти директор сабт мекунад. Амалиёти идоракунӣ дар endpoint-ҳои баррасишуда илова бар узвият ҳолати муассисаро `approved` талаб мекунанд.
- Рӯйхат ва сабти кормандон, синфҳо, тарифҳо, маош ва ҷадвали дарсӣ дар endpoint-ҳои санҷидашуда иҷозати директорро месанҷанд; корбари платформа бо нақши `admin` роҳи алоҳида дорад.
- Ҳангоми сабти ҷадвал, синф ва омӯзгор бо `institutionId` санҷида мешаванд; сарбории фаннӣ, маҳдудиятҳои рӯзона, дастнорасии омӯзгор ва бархӯрди синф/омӯзгор/утоқ низ баррасӣ мешаванд.
- Ҳангоми сабти маош, корманд ва тарифи интихобшуда дар дохили ҳамон муассиса ҷустуҷӯ мешаванд; санаи амали тариф ва соли таҳсил санҷида мешаванд.

Корҳои ҳатмии боқимонда:
- Санҷиши автоматии манфӣ барои корбари муассисаи A, ки мекӯшад маълумоти муассисаи B-ро хонад ё тағйир диҳад.
- Санҷиши endpoint-ҳои боқимонда, махсусан хондан, таҳрир, несткунӣ, боркунии Excel ва ҳуҷҷатҳои формаҳо. Ин баррасӣ ҳамаи endpoint-ҳоро фаро нагирифт.
- Санҷиши воқеӣ бо PostgreSQL 16 ва ду муассисаи озмоишӣ. Хондани код худ аз худ далели гузаштани санҷиши иҷрошаванда нест.

**Ҳолат:** иҷозатҳои як қисми асосии endpoint-ҳо дар код дида шуданд; амнияти пурраи бисёрмуассисавӣ ҳанӯз тасдиқ нашудааст.

### 8. Санҷиши иҷозати API байни муассисаҳо

- Санҷиши интегратсионии `tests/tenantApiAccess.integration.test.ts` илова шуд.
- Он корбари директорро танҳо дар муассисаи А узв мекунад. Барои API-и хондан, дастрасӣ ба муассисаи худ бояд `200`, ба муассисаи Б бошад `403` диҳад. Барои API-и сабт, кӯшиши ворид кардани корманд, синф, хонанда, тариф, маош, давомот, бланка ва дарс дар муассисаи Б бояд `403` баргардонад.
- Санҷиш сессияи имзошудаи воқеӣ ва PostgreSQL-и CI-ро истифода мебарад; агар `DATABASE_URL` / `TEST_DATABASE_URL` набошад, skip мешавад.
- Ҳоло танҳо endpoint-ҳои рӯйхат ва сабти корманд фаро гирифта шудаанд. Барои маош, тариф, хонанда, давомот, бланкаҳо, ҷадвал, таҳрир ва несткунӣ санҷишҳои алоҳида ҳанӯз лозиманд.

### 7. Service Worker ва маҳдудияти офлайн

- Файли `public/sw.js` shell-и барнома ва баъзе дороиҳои статикӣ (script/style/font/image)-ро кеш мекунад; ҳангоми қатъи интернет саҳифаи `index.html`-ро бармегардонад.
- Дар ин Service Worker нигоҳдории маълумоти API, IndexedDB, навбати тағйирот ё механизми sync дида нашуд.
- Аз ин рӯ ҳолати ҳозираро бояд **PWA бо кеши интерфейс** номид, на кори пурраи офлайн. Сабти маълумоти нав ё тағйир додани маълумоти серверӣ бе интернет ҳанӯз тасдиқ нашудааст.

### 7. Ислоҳи тасдиқи муассиса

- Муассиса ҳангоми бақайдгирӣ бо ҳолати `pending` сохта мешавад, аммо endpoint-и маъмурӣ пештар танҳо `approved` ва `suspended`-ро иҷозат медод. Аз ин сабаб Super Admin муассисаи навро тасдиқ карда наметавонист.
- Дар commit-и `67231d2` ин нуқсон ислоҳ шуд: маъмур метавонад муассисаи `pending`-ро тасдиқ кунад, муассисаи `suspended`-ро дубора фаъол намояд ё муассисаи фаъолро боздорад. Ҳар тағйирот бо ҳолати пешина/нав ва сабаб дар audit log сабт мешавад; `approved_by` ва `reviewed_at` ҳангоми тасдиқ пур мешаванд.
- Санҷиши CI барои commit-и нав ҳанӯз тасдиқ нашудааст; пеш аз эълони омодагӣ workflow бояд иҷро шавад ва endpoint бо санҷишҳои автоматӣ фаро гирифта шавад.

## Тартиби афзалиятноки идома

1. Санҷиши fallback-и маҳаллӣ дар CI; баъдан иваз кардани он бо се бланки аслии Excel, вақте ки нусхаҳои аслӣ дастрас шаванд.
2. Санҷиши ҳисобҳо, нигоҳдорӣ ва чоп барои тарификатсия ва табели маош.
3. Санҷиши ҷадвали дарсӣ бо қоидаҳои синф, баст, омӯзгор ва пешгирии бархӯрди соатҳо.
4. Анҷом додани почтаи тасдиқшуда ва ҷараёни рамзи якдафъаина.
5. Анҷом додани офлайн ва ҳамоҳангсозии ҳамаи модулҳо.
6. Борсанҷӣ, амният, backup/restore ва нашри воқеии сервер.

## Қоидаи қабул

Ҳеҷ модул «тайёр» ҳисобида намешавад, то вақте ки маълумот ворид, сабт, баъди бозкушоӣ барқарор, ба Excel/PDF содир ва чопи воқеӣ санҷида нашавад.
